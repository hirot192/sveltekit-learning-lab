# テスト戦略

テストは「速い仕様確認」「実DBとの境界」「ブラウザでの利用者体験」の三層に分ける。失敗した層から、調べる範囲を絞れるようにする。

| 層          | コマンド                     | 主な対象                            | DB                   |
| ----------- | ---------------------------- | ----------------------------------- | -------------------- |
| Unit        | `npm run test:unit -- --run` | validation、純粋関数、教材カタログ  | 原則不要             |
| Integration | `npm run test:db`            | repository、transaction、所有者境界 | PostgreSQL           |
| E2E         | `npm run test:e2e`           | 登録、CRUD、認可、アクセシビリティ  | PostgreSQL + browser |

`npm run check:content` は公開済みの全章に前提知識・目標・処理フロー・ソース・実験があること、教材に記載したソースとMarkdown内のローカルリンクが実在することを検査する。

## アクセシビリティ

Playwright E2Eでは `@axe-core/playwright` を使い、公開ページ、フォーム、ログイン後の主要画面を自動検査する。自動検査だけではキーボード操作の自然さや文章の理解しやすさを完全には判定できないため、次も手動で確認する。

- Tab / Shift+Tabだけで主要操作へ移動でき、フォーカス位置が見える
- 200%拡大と狭い画面でも、情報や操作が失われない
- エラーが色だけでなく文章で示され、入力欄と関連づいている
- OSの「視差効果を減らす」を有効にすると、不要な動きが抑制される
- JavaScriptを無効にしても作成・編集・削除の主要フォームが動く

axeはWCAG違反の一部を高い確度で検出する補助であり、手動確認の代わりではない。
